# 데모용 통화 전사본

녹음 폴더에 넣으면 STT를 건너뛰고 내용을 그대로 판정한다.

```bash
touch docs/samples/통화녹음_카드배달.txt      # ← 빠뜨리지 말 것
adb push docs/samples/통화녹음_카드배달.txt /sdcard/<연결한_폴더>/
```

`adb push` 는 **원본 파일의 수정 시각을 그대로 옮긴다.** 통화 이벤트의 `capturedAt` 은 그
수정 시각이고 세션 시간 창(10분)도 거기서 재므로, 저장소에 오래 있던 파일을 그냥 밀어넣으면
창이 이미 만료돼 뒤따르는 문자가 **다른 세션으로 갈라진다**. 실제로 두 번 겪었다.

## 통화녹음_카드배달.txt

다채널 융합이 필요한 이유를 보여주는 시나리오의 **앞쪽 절반**이다.
뒤쪽 절반은 시뮬레이션 탭의 `카드배달 후속 문자` 버튼이 만든다.

택배기사를 사칭해 "명의도용이 의심되니 금융감독원에 확인해보세요"까지만 말하고 끊는다.
협박도, 계좌 요구도, 이체 지시도 없다 — 규칙은 `CRIMINAL_INVOLVEMENT` 하나로 1단계에서
멈춘다. 사용자에게는 친절한 안내로 읽힌다.

**문자를 보내는 사람은 통화한 그 택배기사다.** 한때 발신자를 `[금융감독원]`으로 뒀다가
되돌렸다 — 피해자가 아직 아무 데도 신고하지 않았는데 기관이 먼저 문자를 보내는 것은 앞뒤가
맞지 않고, 실제 수법도 그렇지 않다. 택배기사가 "확인 접수하실 수 있는 곳을 문자로
보내드릴게요"라고 말한 뒤 자기가 링크를 건넨다. 사칭은 문자의 발신자가 아니라 **그 링크가
데려가는 곳**에서 일어난다.

그래서 이 시나리오는 **같은 사람이 채널을 갈아탄** 경우다. 통화로 믿음을 만들고 문자로
링크를 건넨다. 조각을 따로 보면 통화는 친절한 안내고 문자는 흔한 링크 한 줄이다.

**키워드 대역에서는 등급이 `경보`로 나온다.** `KeywordFilter`가 이분법이라
`명의도용`이 걸리는 순간 최고 등급이 된다. 서버(파인튜닝 모델)를 붙이면 위험도가
33~66 구간에 들어가 `주의보`가 나오고, 후속 문자가 도착해야 `경보`로 올라간다 —
**이 시나리오의 요점이 그 전이라서, 발표 캡처는 서버를 붙인 상태로 찍어야 한다.**
